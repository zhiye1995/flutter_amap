## amap_flutter 导航安装与使用文档（Android / iOS / Web）

本文档面向 `amap_flutter` 插件的**地图 + 导航**能力，重点说明：

- **如何配置 Key / 隐私合规**
- **AndroidManifest.xml 需要哪些权限/声明**
- **如何启动导航页面与监听导航事件**

> 说明：当前插件的 **`AMapNavi`（导航组件/内置路线规划页）仅支持 Android**。iOS 侧仅包含地图能力（`MAMapKit`），未实现对应导航通道。

---

## 依赖安装

在 `pubspec.yaml` 增加依赖：

```yaml
dependencies:
  amap_flutter: ^<your_version>
```

然后执行：

```bash
flutter pub get
```

---

## 获取高德 Key

在高德开放平台控制台创建应用并获取 Key（Android/iOS/Web 需分别创建/绑定包名与签名等信息）。

- **控制台**：`https://console.amap.com/dev/key/app`
- **Key 对应关系**：
  - **Android Key**：用于 Android 原生 SDK（地图/导航）
  - **iOS Key**：用于 iOS 原生 SDK（地图）
  - **Web Key**：用于 Web JS SDK（Web 端地图）

---

## Flutter 侧初始化（必做）

在展示 `AMapFlutter` 地图组件或调用 `AMapNavi` 导航前，必须先初始化：

```dart
await AMapFlutter.init(
  apiKey: ApiKey(
    iosKey: '<iOS Key>',
    androidKey: '<Android Key>',
    webKey: '<Web Key>',
  ),
  agreePrivacy: true,
);
```

### 隐私合规说明（非常重要）

- `agreePrivacy: true` 会在原生侧调用 SDK 的隐私合规 API（Android: `MapsInitializer.updatePrivacy...`；iOS: `MAMapView.updatePrivacy...`）。
- **请确保你已经在 UI 中展示隐私政策并获得用户同意后，才传 `true`**；否则请传 `false` 并在用户同意后再次调用初始化/同意接口。

## Android 配置

下面内容以 **`example/android/app/src/main/AndroidManifest.xml`** 为参考，按“必需/可选”拆解。

### 1) AndroidManifest.xml：权限（必需 + 可选）

#### 最小必需（地图/导航一般都需要）

```xml
<uses-permission android:name="android.permission.INTERNET" />
<uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION" />
<uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />
```

#### 导航体验推荐（可选）

```xml
<!-- 导航中保持常亮（可选） -->
<uses-permission android:name="android.permission.WAKE_LOCK" />
```

#### 后台定位（仅在你确实需要时添加）

> 如果你的 App 需要在后台持续定位，并且 `targetSdkVersion >= 29`，才考虑添加：

```xml
<uses-permission android:name="android.permission.FOREGROUND_SERVICE" />
<uses-permission android:name="android.permission.ACCESS_BACKGROUND_LOCATION" />
```

#### 蓝牙相关（仅在你需要提升室内定位/蓝牙扫描时添加）

示例中包含了 `BLUETOOTH*` 权限；如果你并不使用蓝牙能力，可以不加，避免不必要的权限弹窗/合规成本。

---

### 2) AndroidManifest.xml：设置 `com.amap.api.v2.apikey`（强烈建议）

虽然插件的 `AMapFlutter.init()` 会在 Android 侧调用 `MapsInitializer.setApiKey(androidKey)`，但**高德内置的路线规划/导航页面**在不少场景仍依赖 Manifest 的 `meta-data`。

在 `<application>` 内添加：

```xml
<meta-data
    android:name="com.amap.api.v2.apikey"
    android:value="<你的 Android Key>" />
```

---

### 3) AndroidManifest.xml：定位服务 `APSService`（按需）

如果你需要定位能力（如显示当前位置/导航定位），建议声明：

```xml
<service android:name="com.amap.api.location.APSService" />
```

> 注意：声明服务并不等于已授权定位权限；你仍需在运行时申请权限（见下文）。

---

### 4) 导航页面 Activity（通常无需手动添加）

插件在 `android/src/main/AndroidManifest.xml` 内已经声明了自定义承载页：

- `com.morbit.amap_flutter.AMapFlutterRouteActivity`

这意味着在大多数情况下（**Manifest Merge 正常开启**），你的 App **不需要**再手动添加任何导航 Activity 声明。

#### 什么时候需要你手动声明？

- 你关闭/绕过了 Manifest merge（极少见）
- 你想在宿主侧覆盖 theme / `configChanges` 等属性

此时可以在宿主 App 的 `<application>` 中显式声明（保持类名一致）：

```xml
<activity
    android:name="com.morbit.amap_flutter.AMapFlutterRouteActivity"
    android:configChanges="orientation|keyboardHidden|screenSize|navigation"
    android:launchMode="singleInstance"
    android:theme="@android:style/Theme.Light.NoTitleBar" />
```

> 备注：`example/android/.../AndroidManifest.xml` 里声明了 `com.amap.api.navi.AmapRouteActivity`，但本插件启动导航时使用的是 `AMapFlutterRouteActivity`；通常你可以不声明 `AmapRouteActivity`（除非你自行调用了 SDK 的默认页面）。

---

### 5) 运行时权限（必做）

Android 6.0+ 必须在运行时申请定位权限。插件不会自动弹窗请求。

示例工程使用 `permission_handler`：

```dart
import 'package:permission_handler/permission_handler.dart';

Future<void> requestLocationPermission() async {
  final status = await Permission.location.status;
  if (status.isGranted) return;
  final result = await Permission.location.request();
  if (result.isPermanentlyDenied) {
    await openAppSettings();
  }
}
```

## iOS 配置（地图）

### 1) 设置 iOS Key

iOS 的 Key 通过 `AMapFlutter.init(apiKey: ...)` 下发到原生（`AMapServices.shared().apiKey = iosKey`），无需在 `Info.plist` 里额外写 `apikey`。

### 2) Info.plist：定位权限描述（按需）

如果你需要定位（显示当前位置/跟随等），请在 `ios/Runner/Info.plist` 添加：

```xml
<key>NSLocationWhenInUseUsageDescription</key>
<string>需要访问您的位置以在地图上显示当前位置</string>
```

若你需要后台定位（不推荐，且合规要求更高），再补充：

```xml
<key>NSLocationAlwaysAndWhenInUseUsageDescription</key>
<string>需要后台访问您的位置以提供持续定位服务</string>
```

### 3) ATS（网络）说明

示例工程在 `Info.plist` 里启用了：

```xml
<key>NSAppTransportSecurity</key>
<dict>
  <key>NSAllowsArbitraryLoads</key>
  <true/>
</dict>
```

这会放开所有网络限制，**建议你按自己的安全策略收敛**；如果不加且网络请求失败，再根据报错有针对性地配置 ATS。

## 导航（Android）：使用方式与注意事项

### 1) 基本用法

```dart
// 建议：提前订阅事件（initState）以避免错过首批回调
final sub = AMapNavi.onNaviInfoUpdate.listen((event) {
  debugPrint('剩余距离: ${event.naviInfo.pathRetainDistance}m');
});

// 启动导航/路线规划页
await AMapNavi.startNavigation(
  config: NaviConfig(
    naviType: NaviType.driver,      // driver / walk / ride
    pageType: NaviPageType.route,   // route / navi
    start: null, // 不传：默认使用当前位置
    end: NaviPoint(
      position: Position(latitude: 39.908, longitude: 116.397),
      name: '天安门',
    ),
    wayPoints: [
      // 可选：途经点
      // NaviPoint(position: Position(...), name: 'xxx'),
    ],
    carNumber: '渝A12345', // 可选：限行规避
  ),
);

// 退出/停止导航（建议在页面 dispose / 业务结束时调用）
await AMapNavi.stopNavigation();
await sub.cancel();
```

### 2) `NaviConfig` 字段说明（与当前代码实现一致）

- `naviType`：导航类型（`driver` / `walk` / `ride`）
- `pageType`：页面类型
  - `route`：先展示路线规划页
  - `navi`：直接进入导航页（前提是参数足够，且路线可计算）
- `start`：起点
  - `null`：默认使用当前位置（需要定位权限与定位可用）
- `end`：终点
  - `null`：会进入路线规划页，让用户自行选择终点（适合“只想打开路线规划页”场景）
- `wayPoints`：途经点列表（可空）
- `carNumber`：车牌号（可选，限行相关）
- `motorcycleCC`：摩托车排量（可选）

### 3) 事件流（建议至少监听退出/失败）

`AMapNavi` 提供一组 `Stream` 事件（均为广播流），常用的有：

- `onNaviInitSuccess` / `onNaviInitFailure`
- `onNaviStart`
- `onNaviInfoUpdate`（引导信息：剩余距离/时间、下一路名、转向图标等）
- `onNaviLocationChange`
- `onNaviText`（语音播报文本，便于自定义播报）
- `onNaviArriveDestination`
- `onNaviExit`（用户退出导航页/关闭页面）
- `onNaviRouteCalculateSuccess` / `onNaviRouteCalculateFailure`

> 插件内部会根据 `initFailure / arriveDestination / calculateRouteFailure / exitPage / endEmulatorNavi` 等事件自动把 `AMapNavi.isNavigating` 置回 `false`，你也可以用 `AMapNavi.isNavigatingListenable` 直接驱动 UI。

### 4) 常见坑点清单

- **没配置 `com.amap.api.v2.apikey`**：内置导航页可能初始化失败或直接黑屏；请在 AndroidManifest `<application>` 内补上。
- **没申请运行时定位权限**：`start` 为 `null` 时依赖当前位置，可能导致路线计算失败或定位不更新。
- **订阅没取消导致重复回调**：导航页多次进出时，请在 `dispose()` 里取消订阅并调用 `AMapNavi.stopNavigation()`。
- **沉浸式/状态栏问题**：插件使用 `AMapFlutterRouteActivity` 处理系统栏与安全区；如果你自定义主题/沉浸式，请优先覆盖该 Activity 的 theme，而不是声明 `AmapRouteActivity`。

## FAQ

### Q1：为什么我地图能显示，但导航页打不开/黑屏？

优先检查：

- AndroidManifest 是否配置了 `com.amap.api.v2.apikey`
- 是否授予定位权限（尤其 `start` 为空时）
- 是否使用了真机且网络可用（模拟器/无定位可能影响导航）

### Q2：`AMapNavi.startNavigation` 调用成功但没有任何事件？

- 确保你在页面 `initState` 就开始订阅事件（不要等到点击后才订阅）
- 确保没有被反复创建但未取消订阅（会导致你以为“没回调”，实际回调打到旧订阅上）
