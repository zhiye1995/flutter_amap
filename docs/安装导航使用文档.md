## amap_flutter 导航安装与使用文档（Android / iOS / Web）

本文档面向 `amap_flutter` 插件的**地图 + 导航**能力，重点说明：

- **如何配置 Key / 隐私合规**
- **AndroidManifest.xml / Info.plist 需要哪些权限/声明**
- **如何启动导航页面与监听导航事件**

> 说明：当前插件的 **`AMapNavi`（导航组件/内置路线规划页）支持 Android 和 iOS 平台**。Web 端仅包含地图能力。

---

## 依赖安装

在 `pubspec.yaml` 增加依赖：

```yaml
dependencies:
  flutter_ amap: ^<your_version>
```

然后执行：

```bash
flutter pub get
```

---

## 获取高德 Key

在高德开放平台控制台创建应用并获取 Key（Android/iOS/Web 需分别创建/绑定包名与签名等信息）。

- **控制台**：`https://console.amap.com/dev/key/app`
- **Key 对应关系**：
  - **Android Key**：用于 Android 原生 SDK（地图/导航）
  - **iOS Key**：用于 iOS 原生 SDK（地图/导航）
  - **Web Key**：用于 Web JS SDK（Web 端地图）

---

## Flutter 侧初始化（必做）

在展示 `AMapFlutter` 地图组件或调用 `AMapNavi` 导航前，必须先初始化：

```dart
await AMapFlutter.init(
  apiKey: ApiKey(
    iosKey: '<iOS Key>',
    androidKey: '<Android Key>',
    webKey: '<Web Key>',
  ),
  agreePrivacy: true,
);
```

### 隐私合规说明（非常重要）

- `agreePrivacy: true` 会在原生侧调用 SDK 的隐私合规 API（Android: `MapsInitializer.updatePrivacy...`；iOS: `MAMapView.updatePrivacy...`）。
- **请确保你已经在 UI 中展示隐私政策并获得用户同意后，才传 `true`**；否则请传 `false` 并在用户同意后再次调用初始化/同意接口。

## Android 配置

下面内容以 **`example/android/app/src/main/AndroidManifest.xml`** 为参考，按“必需/可选”拆解。

### 1) AndroidManifest.xml：权限（必需 + 可选）

#### 最小必需（地图/导航一般都需要）

```xml
    <!-- 允许程序请求网络，用于访问互联网资源 -->
    <uses-permission android:name="android.permission.INTERNET" />
    <!-- 允许程序访问CellID或WiFi热点来获取粗略的位置，用于网络定位 -->
    <uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION" />
    <!-- 获取运营商信息和网络状态，用于支持提供运营商信息相关的接口 -->
    <uses-permission android:name="android.permission.ACCESS_NETWORK_STATE" />
    <!-- 用于访问GPS定位，获取精确的地理位置信息 -->
    <uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />

    <!-- 允许获取wifi状态改变，用于网络定位 -->
    <uses-permission android:name="android.permission.CHANGE_WIFI_STATE" />
    <!-- 用于访问wifi网络信息，wifi信息会用于进行网络定位 -->
    <uses-permission android:name="android.permission.ACCESS_WIFI_STATE" />
```

#### 导航体验推荐（可选）

```xml
    <!-- 用于导航状态中保持屏幕常亮，防止设备休眠 -->
    <uses-permission android:name="android.permission.WAKE_LOCK" />
```



---

### 2) AndroidManifest.xml：设置 `com.amap.api.v2.apikey`（强烈建议）

虽然插件的 `AMapFlutter.init()` 会在 Android 侧调用 `MapsInitializer.setApiKey(androidKey)`，但**高德内置的路线规划/导航页面**在不少场景仍依赖 Manifest 的 `meta-data`。

在 `<application>` 内添加：

```xml
<meta-data
    android:name="com.amap.api.v2.apikey"
    android:value="<你的 Android Key>" />
```

---

### 3) AndroidManifest.xml：定位服务 `APSService`（按需）

如果你需要定位能力（如显示当前位置/导航定位），建议声明：

```xml
<service android:name="com.amap.api.location.APSService" />
```

> 注意：声明服务并不等于已授权定位权限；你仍需在运行时申请权限（见下文）。



### 4) 代码混淆（ProGuard / R8）

当你打包 **release** 并开启 **R8/ProGuard**（`minifyEnabled true`）时，需要为高德 SDK 添加 keep 规则，否则可能出现**导航页黑屏/初始化失败/语音不可用**等问题。

本插件已在 Android library 内置了 `consumerProguardFiles`（对应 `android/consumer-rules.pro`），**多数情况下你不需要额外手动配置**；但如果你项目有自定义混淆规则、或升级/替换依赖后出现崩溃/警告，可在你的 App `proguard-rules.pro` 追加以下内容：

```pro
## 3D 地图（V5.0.0 之后通用）
-keep class com.amap.api.maps.** { *; }
-keep class com.autonavi.** { *; }
-keep class com.amap.api.trace.** { *; }

## 2D 地图（如你显式集成了 2D 组件）
-keep class com.amap.api.maps2d.** { *; }
-keep class com.amap.api.mapcore2d.** { *; }

## 定位
-keep class com.amap.api.location.** { *; }
-keep class com.amap.api.fence.** { *; }
-keep class com.autonavi.aps.amapapi.model.** { *; }

## 搜索
-keep class com.amap.api.services.** { *; }

## 导航
-keep class com.amap.api.navi.** { *; }

## 导航语音相关（不同版本 Navi SDK 可能引入的包名不同；这里做并集以保证兼容）
-keep class com.alibaba.idst.nui.** { *; }     # Navi V8.1.0+ 常见（你提到的“新增代码混淆”）
-keep class com.alibaba.idst.nls.** { *; }     # Navi V7.3.0 以前常见
-keep class com.alibaba.mit.alitts.** { *; }   # Navi V7.3.0+ 常见
-keep class com.nlspeech.nlscodec.** { *; }    # Navi V7.3.0 以前常见

## 部分版本 SDK 可能引用 Google 包（按官方建议保留）
-keep class com.google.** { *; }
```

如果编译时仍有 warning，可按 warning 提示对对应包名添加（示例）：

```pro
-dontwarn com.alibaba.**
-dontwarn com.amap.**
-dontwarn com.autonavi.**
```

## iOS 配置（地图 + 导航）

### 1) 设置 iOS Key

iOS 的 Key 通过 `AMapFlutter.init(apiKey: ...)` 下发到原生（`AMapServices.shared().apiKey = iosKey`），无需在 `Info.plist` 里额外写 `apikey`。

### 2) Info.plist：定位权限描述（必需）

导航功能需要定位权限，请在 `ios/Runner/Info.plist` 添加：

```xml
<key>NSLocationWhenInUseUsageDescription</key>
<string>需要访问您的位置以提供导航服务</string>
```

若你需要后台定位（导航时 App 进入后台仍需定位），再补充：

```xml
<key>NSLocationAlwaysAndWhenInUseUsageDescription</key>
<string>需要后台访问您的位置以提供持续导航服务</string>
```

并在 `UIBackgroundModes` 中添加 `location`：

```xml
	<key>UIBackgroundModes</key>
	<array>
      <string>location</string>
      <string>audio</string>
      <string>bluetooth-central</string>
	</array>
```

### 3) ATS（网络）说明

示例工程在 `Info.plist` 里启用了：

```xml
<key>NSAppTransportSecurity</key>
<dict>
  <key>NSAllowsArbitraryLoads</key>
  <true/>
</dict>
```

这会放开所有网络限制，**建议你按自己的安全策略收敛**；如果不加且网络请求失败，再根据报错有针对性地配置 ATS。

### 4) 运行时权限（必做）

iOS 同样需要在运行时请求定位权限。使用 `permission_handler`：

```dart
import 'package:permission_handler/permission_handler.dart';

Future<void> requestLocationPermission() async {
  final status = await Permission.locationWhenInUse.status;
  if (status.isGranted) return;
  final result = await Permission.locationWhenInUse.request();
  if (result.isPermanentlyDenied) {
    await openAppSettings();
  }
}
```

## FAQ

### Q1：为什么我地图能显示，但导航页打不开/黑屏？

**Android**：
- AndroidManifest 是否配置了 `com.amap.api.v2.apikey`
- 是否授予定位权限（尤其 `start` 为空时）
- 是否使用了真机且网络可用（模拟器/无定位可能影响导航）

**iOS**：

- Info.plist 是否配置了 `NSLocationWhenInUseUsageDescription`
- 是否在运行时请求并获得了定位权限
- 是否在真机上运行（模拟器定位受限）

### Q2：`AMapNavi.startNavigation` 调用成功但没有任何事件？

- 确保你在页面 `initState` 就开始订阅事件（不要等到点击后才订阅）
- 确保没有被反复创建但未取消订阅（会导致你以为"没回调"，实际回调打到旧订阅上）

### Q3：iOS 导航页面如何关闭？

- 用户可以点击导航页面左上角的"关闭"按钮
- 代码中调用 `AMapNavi.stopNavigation()` 会自动关闭导航页面

### Q4：iOS 和 Android 导航 API 有什么区别？

从 Flutter 层面来说，两个平台使用完全相同的 API（`AMapNavi` 类），事件格式也保持一致。平台差异主要体现在：
- 导航 UI 风格略有不同（各平台原生 SDK 提供）
- 部分字段在 iOS/Android 上的具体数值可能有差异（如 iconType 枚举值）
